Part 1: The Compute Crisis • Suhail Alam (3 Mins)

Why CPUs Fail at Modern AI Workloads

The fundamental architectural divide: Low-latency serial processing vs massive matrix parallelism.

🚅
Central Processing Unit (CPU)
Engineered for sequential execution, operating systems, and complex logic branching.
  • 8 to 32 Heavy Cores: High clock speed (4-5 GHz).
  • Bullet Train Analogy: Carries few passengers at very high speed.
  • The AI Problem: Chokes on billions of simultaneous matrix operations ($O(N^3)$ loops).
⚡
Graphics Processing Unit (GPU)
Engineered for high-throughput parallel linear algebra and tensor matrix math.
  • 10,000+ Stream Processors: Massive concurrency.
  • Highway Analogy: 10,000 lanes moving millions of data points at once.
  • The AI Triumph: Computes entire matrix multiplications in single clock cycles.

Part 2: Silicon Engineering • Harsh Mishra (8.5 Mins)

The FP8 Transformer Engine Revolution

Halving memory footprint and doubling compute throughput with zero loss in mathematical convergence.

Precision Evolution in Modern AI

• FP32 (Single Precision - 32 bits): Standard scientific precision. High memory footprint, saturates memory bus.

• FP16 / BF16 (Half Precision - 16 bits): Standard for modern LLMs. Cuts VRAM in half, doubles throughput.

• FP8 (Hopper Innovation - 8 bits): Two formats:
  → E4M3 (4 exponent, 3 mantissa) for forward activations.
  → E5M2 (5 exponent, 2 mantissa) for backward gradients.

Autonomous Dynamic Range Scaling
The Transformer Engine dynamically monitors layer tensors:
  • Maintains FP8 when tensor values fit within safe bounds.
  • Dynamically scales scaling factors per layer per step.
  • Falls back to FP16 seamlessly if gradient underflow is detected.
  • Result: 3x Faster Training, 80GB VRAM behaves like 160GB!

Part 2: Distributed Interconnect • Harsh Mishra (8.5 Mins)

NVLink 4 & NVSwitch: Multi-GPU Mesh

Scaling beyond a single GPU: Connecting 8x H100s into a unified 640 GB super-device.

Traditional PCIe Gen 5 Bottleneck
Standard server motherboards link GPUs over PCIe buses:
  • Capped at 64 GB/s bidirectional bandwidth.
  • Data must route through CPU root complex and host memory.
  • Severe communication bottleneck during multi-GPU gradient all-reduce.
4th Gen NVLink & NVSwitch
Direct high-speed GPU-to-GPU interconnect:
  • 900 GB/s per GPU bidirectional bandwidth (7x faster than PCIe 5).
  • NVSwitch fabric provides full crossbar all-to-all connectivity.
  • Enables zero-latency Tensor Parallelism across 8 H100s.

Part 3: Distributed Systems • Mirza Saad Beg (7.5 Mins)

Multi-Node Orchestration: DDP & FSDP

Scaling models that exceed 80 GB across high-performance distributed cloud clusters.

Distributed Data Parallel (DDP)

• Model is replicated across all GPUs.

• Each GPU processes a distinct batch of data in parallel.

• Gradients are synchronized using All-Reduce over 900 GB/s NVLink.

• Limitation: Model parameters must fit in single GPU VRAM (80 GB).

Fully Sharded Data Parallel (FSDP)

• Implements ZeRO-3 (Zero Redundancy Optimizer).

• Shards model weights, gradients, and optimizer states across nodes.

• Parameters are all-gathered on-the-fly and freed immediately.

• Superpower: Train 70B+ parameter models on multi-H100 clusters seamlessly.
